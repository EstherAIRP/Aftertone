# 殘響日誌 Aftertone — MVP 開發計畫

本計畫以 [MVP_SPEC.md](MVP_SPEC.md) 為基礎，並納入 2026-10-02 訪談決策。若兩份文件有衝突，實作以本計畫的「已確認決策」為準；開發前應同步修訂規格書。

## 1. 交付目標

交付一個手機優先、可安裝的私人 PWA。使用者以 GitHub 帳號登入，在手機或電腦快速記錄耳鳴事件，取得不可編輯的意象片段；隔天起可將某日片段組成中英兩份可編輯的「今日 Prompt」，複製到自行選擇的圖像生成工具，稍後上傳一張圖片，並在收藏中回顧作品與原始紀錄。

網站程式碼由 GitHub 部署至 Vercel。事件、Prompt 與原圖同步到同一個私人 GitHub 倉庫的獨立資料分支；瀏覽器保留離線副本，連線後自動同步。未登入者只看到登入畫面，沒有公開介紹頁或公開畫廊。MVP 不提供內建圖像生成、翻譯 API 或額外的匯出／匯入功能。

## 2. 已確認決策與行為規則

| 主題 | MVP 規則 |
| --- | --- |
| 平台與部署 | 手機優先 PWA；GitHub 連動 Vercel；手機與電腦都可新增紀錄。 |
| 存取權限 | 全站需 GitHub 登入，且只允許指定的本人帳號；曾登入的裝置離線時可使用本機資料。 |
| 資料同步 | 私人倉庫的獨立資料分支為跨裝置同步來源；本機 IndexedDB 支援離線新增，連線後自動同步。資料不另做端對端加密。 |
| 圖像來源 | 使用者複製 Prompt 到外部工具生成圖片，再回來上傳；產品不呼叫圖像生成 API。 |
| 每次紀錄 | 儲存事件後，從當日尚未取得的七個主要類別隨機抽一類，產生唯讀片段。七類用完後改抽細節類別。連線時抽完即同步；離線時先抽，衝突後可調整片段。 |
| 完成日期 | 某日期結束後才能完成其 Prompt：最早在該日期的隔天。可補做更早、尚未完成的日期。 |
| 補記與編修 | 新增時可選今天或尚未完成的過去日期；儲存後日期不可修改，其他紀錄欄位可修改。事件可刪除，包括已完成日期的事件；已完成日期不再新增事件。只有新增事件會抽取 Prompt，修改或刪除不抽取。 |
| 今日 Prompt | 片段列表不可編輯；組合後的繁中與英文完整 Prompt 各自可編輯、複製並保存，兩個版本不自動同步。 |
| 編修後的作品 | 修改事件只更新事件列表與摘要，不改 Prompt list。刪除事件時一併移除其 Prompt list 片段，並更新事件摘要；今日 Prompt、標題及圖片保持原樣。 |
| 圖像收藏 | 完成 Prompt 即建立一筆沒有圖片的待上傳作品；圖片可日後補上。每日期一張，可刪除或替換；原圖不壓縮。 |
| 圖片大小 | 網站直接上傳限制約 4 MB。較大原圖由使用者依固定日期路徑手動放入資料分支，再按「重新同步」偵測。 |
| 同步衝突 | 不同裝置修改同一筆資料時，最後成功同步的版本生效；跨裝置離線抽到重複類別時，重算後提示變更。 |

「今天」與事件歸屬日期以裝置當地時區計算。跨日後，首頁應提供未完成日期的入口。Prompt list、今日 Prompt 與圖片是獨立欄位；事件刪除只移除對應片段，不覆蓋已編輯的今日 Prompt。

## 3. 範圍與頁面

1. **首頁**：今日日期與紀錄次數、主要記錄按鈕、最近片段、今日累積狀態、未完成的過去日期入口、收藏入口。
2. **記錄流程**：單頁短表單，預填目前時間；提交後顯示抽中的類別與片段。表單驗證、儲存與抽取須作為同一筆操作，避免只有事件或只有片段。
3. **日期意象頁**：可切換今天及未完成的過去日期，查看事件、七類狀態、唯讀片段與組合草稿。今天僅能預覽，過去日期可編輯中英 Prompt、複製並完成。
4. **收藏與詳情**：已完成作品以日期、標題、圖片或待上傳佔位呈現；詳情包含中英 Prompt、片段來源、事件摘要和原始事件。支援上傳、替換、刪除單張圖片，以及較大圖片的手動路徑與重新同步。
5. **登入與同步狀態**：未登入顯示登入畫面；登入後顯示目前是已同步、待同步、同步中或同步失敗。曾登入的裝置離線時可繼續記錄。
6. **PWA 基礎**：安裝資訊、應用程式外殼離線快取、手機操作與基本無障礙支援。離線編輯先存本機；GitHub 同步與圖片上傳需連線。

## 4. 技術設計

- **前端**：Vue 3、TypeScript、Vite、Vue Router、Pinia。核心規則放在純函式模組，頁面只負責輸入與呈現。
- **登入與授權**：登入流程由 Vercel 端點處理，瀏覽器只持有安全 session；伺服端核對 GitHub 帳號 allowlist，且僅授權指定私人倉庫。GitHub 寫入憑證只存 Vercel 環境變數，不送到瀏覽器。離線時依此裝置先前成功登入的狀態開啟本機副本；恢復連線後重新驗證再同步。
- **儲存與同步**：IndexedDB 保存 `events`、`daily_states`、`artworks`、圖片 Blob、待同步操作及同步游標；使用明確的 schema 版本與遷移函式。GitHub 資料分支按日期與事件 ID 分檔，Vercel 端點負責讀寫與權限檢查。程式碼分支部署網站，資料分支不觸發 Vercel 部署。資料分支為跨裝置同步來源，本機寫入先提交佇列，再依序上傳；每次寫入使用版本比對與衝突重試。
- **日期鍵**：`YYYY-MM-DD` 當地日期；事件另存帶時區資訊的時間戳。建立事件時先驗證目標日期尚未完成；儲存後鎖定日期，若調整時間也不得跨日。
- **抽取與映射**：只有新增事件會抽取片段。七個主要類別當日不重複，抽中類別與映射後的中英片段一同保存。細節類別可重複，但須限制片段總長度，避免 Prompt 無限膨脹。修改事件不觸發抽取，也不改動片段；刪除事件不觸發抽取，但會刪除其對應片段，未完成日期因此釋出的主要類別可供後續新事件抽取。離線新增先暫定片段；同步時若跨裝置出現重複主要類別，依事件時間與 ID 的穩定排序重新分配衝突片段，並在介面提示。
- **雙語 Prompt**：為每個規則式片段提供繁中和英文文案，再依固定類別順序組合成雙語草稿。使用者可分別修改兩個完整版本；保存時保留系統草稿、最終版本與修改時間，便於回顧片段來源。
- **完成與編修**：再次確認日期已結束、至少有一筆事件、尚未完成，保存最終 Prompt 與作品。完成後可修改原事件，僅更新事件列表和摘要；刪除原事件會再移除其 Prompt list 片段。完整 Prompt、標題與圖片保持原樣。離線操作須有唯一操作 ID，避免重送造成重複完成。
- **圖片處理**：接受常見圖片格式，保留原檔，不縮放或壓縮。小於約 4 MB 的圖片由網站上傳到資料分支；大圖顯示固定路徑，讓使用者自行提交到同一私人倉庫資料分支，再按「重新同步」偵測。畫廊使用可安全傳送的預覽圖，原圖保持原狀；替換失敗時保留舊圖。圖片顯示時建立並釋放 object URL。
- **刪除與衝突**：刪除事件以 tombstone 同步，避免其他裝置的舊副本將它復活。修改衝突採最後成功同步版本；介面不顯示版本歷史，但需說明私人 Git 倉庫仍保留過去提交。

資料結構至少需補充 `date`、`fragment_id`、`category`、雙語片段文字、`draft_prompt_zh/en`、`final_prompt_zh/en`、`completed_at`、`updated_at`、刪除標記、同步狀態、作品圖片路徑及 schema 版本。`daily_artworks.image_url` 改為可空的私人倉庫圖片路徑；`event_count` 與摘要依目前未刪除的事件計算。

## 5. 實作階段與驗收

以一位開發者兼設計、兼職投入估算。以下為工作量區間，不含等待 GitHub 應用程式審核或使用者測試的時間。

| 階段 | 估計 | 交付內容 | 階段驗收 |
| --- | --- | --- | --- |
| 0. 規格對齊與介面草圖 | 3–4 工作日 | 同步規格、頁面流程、資料 schema、同步狀態與空狀態；完成「冰藍殘響」色票、字體與首頁／記錄／收藏草圖 | 規格不再描述內建圖像生成或純本機資料；日期與作品規則無矛盾；主要頁面使用一致視覺語言。 |
| 1. 專案、部署與登入 | 5–7 工作日 | Vue/PWA 骨架、GitHub 連動 Vercel、登入與帳號 allowlist、私人 API 端點 | 未登入無法取得資料；指定帳號可登入；資料分支提交不觸發網站部署。 |
| 2. 事件與離線儲存 | 5–7 工作日 | 短表單、IndexedDB、待同步佇列、事件新增／編修／刪除 | 手機數秒內完成一次紀錄；離線可新增；重新開啟後資料與待同步狀態仍在。 |
| 3. 片段與跨裝置同步 | 7–10 工作日 | 雙語映射、類別抽取、資料分支讀寫、衝突重試與重新同步 | 同日七類不重複；兩裝置離線新增後可合併；片段調整有提示；編修事件不抽卡。 |
| 4. 完成與雙語 Prompt | 4–6 工作日 | 日期意象頁、中英完整 Prompt 編輯／複製、作品完成 | 今天無法完成；過去日期可完成一次；事件修改不覆蓋 Prompt，刪除只移除對應片段。 |
| 5. 圖片與收藏 | 6–9 工作日 | 原圖上傳、手動路徑與重新同步、預覽圖、替換／刪除、畫廊與詳情 | 小圖自動上傳；大圖手動提交後可偵測；未上傳圖片的作品可回顧。 |
| 6. 驗證與發佈 | 4–6 工作日 | 權限、離線同步、手機與電腦、容量與失敗復原、正式部署 | 從記錄到上傳完整閉環通過；未登入不可讀取；離線操作連線後完成同步。 |

總工作量約 **34–49 工作日**；若每週投入 2–3 個工作日，約需 **12–25 週**。上線時至少驗證一款 iOS 瀏覽器、一款 Android 瀏覽器與一款桌面瀏覽器，並檢查安裝後、重新開啟、離線、雙裝置同步與 session 到期狀態。此估算以現有倉庫只有規格書、需從零建置為前提。

## 6. 必測情境

- 一天記錄 1、7、8 次時，主要類別抽取與細節片段皆符合規則；快速連點不產生重複事件或重複主要類別。
- 23:59 與 00:01 的事件分屬正確日期；今天不可完成，隔天可完成前一天，較早未完成日期也可補做。
- 不能向已完成日期新增事件；儲存後不可更改事件日期。修改事件不抽新片段，刪除事件移除其 Prompt list 片段；今日 Prompt 與圖片不變，事件摘要更新。
- 繁中、英文草稿各自可編輯與複製；重新開啟後保存版本一致；唯讀片段未被改動。
- 沒有圖片也能完成並在收藏中找到作品；小圖自動上傳，大圖按固定路徑手動提交並重新同步；替換失敗不丟舊圖。
- 未登入或非允許帳號無法讀取私人資料；GitHub 憑證不出現在前端輸出、日誌或公開回應中。
- 離線新增的事件與片段在連線後自動同步；兩台裝置離線時抽到同類別，合併結果可調整且有提示。
- 同一事件的跨裝置編修以最後成功同步版本為準；刪除事件不會被舊離線副本復活。
- 儲存容量不足、圖片格式錯誤、GitHub API 暫時失敗與瀏覽器拒絕儲存時，有可理解的提示且不破壞既有資料。
- 畫面文案不把耳鳴次數呈現成獎勵、進度挑戰或健康評分；不提供醫療建議。
- 「冰藍殘響」的柔光背景與圓軌不遮擋表單、Prompt 或作品；觸控目標至少 44 × 44 px，文字對比與鍵盤焦點清晰，動態遵守減少動態偏好。

## 8. 技術邊界與待實作驗證

- Vercel Function 的請求或回應本文上限為 4.5 MB，因此網站直接傳送原圖先限制約 4 MB；較大原圖採手動提交。手動圖若超過 GitHub 網頁上傳限制，須改用本機 Git 工具。完整原圖保留在私人資料分支，畫廊以另外生成的私人預覽圖顯示。[Vercel 限制](https://vercel.com/docs/functions/limitations)、[GitHub 檔案限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)
- GitHub 建議一般 Git 物件小於 1 MB，且大型圖片與頻繁提交會逐漸拖慢倉庫；正式實作前以數十張原圖測試同步速度，必要時重新評估圖片儲存方案。[GitHub 倉庫限制](https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits)
- Vercel 預設對連動倉庫的新提交建立部署；資料分支必須設定為不部署，並用實際提交驗證。[Vercel 專案設定](https://vercel.com/docs/project-configuration/project-settings)

## 9. UI 風格 — 冰藍殘響

**定位**：參考清晨窗邊的柔光與霧面玻璃，把日誌做成安靜、私密、留白充足的介面。同心圓指向「記下一次」的入口，不代表收集進度。完整逐頁與圖片規劃見 [UI_DESIGN_PLAN.md](UI_DESIGN_PLAN.md)。

| 設計元素 | 方向 |
| --- | --- |
| 基礎色 | 冰白背景 `#F5F8FC`、深藍灰文字 `#34445D`、淡藍灰輪廓。 |
| 操作色 | 深藍 `#47648A` 用於主要按鈕；玻璃卡片保持足夠不透明度。 |
| 字體與形狀 | 中文標題用襯線、長文與表單用黑體；細線同心圓、膠囊選項、克制的圓角卡片。 |
| 圖片 | 共用窗邊柔光 WebP 只作背景；每日作品由使用者提供，空收藏不顯示假作品。 |
| 動態 | 僅短暫淡入與按壓反饋；支援 `prefers-reduced-motion`。 |

**頁面落點**：首頁先呈現日期、今日摘要與大型圓形記錄入口；記錄頁以清楚表單為主；日期頁把唯讀片段與可編輯 Prompt 分開；收藏讓使用者作品圖片成為焦點。同步與錯誤提示始終使用可讀文字。

**文案語氣**：溫柔、簡短、平實，例如「把今天的一點聲音，輕輕記下來。」記錄成功可寫「今天的意象多了一段描述。」避免以慶祝動畫、滿罐進度或角色反應鼓勵增加耳鳴紀錄。
